Title: Privacy-Safe Click Analytics — Salted IP Hashing for GDPR Compliance
Demonstrated: Every redirect records a ClickEvent with a SHA-256 hash of the client IP (never the raw address), a truncated User-Agent, and a referrer. Analytics remain useful; PII is irrecoverable.
Technical detail: recordClickEvent() computes createHash('sha256').update(`${IP_HASH_SALT}:${ip}`).digest('hex'). The salt is a per-deployment env var — different deployments produce different hashes for the same IP, blocking cross-installation rainbow tables. User-Agent and Referrer are truncated to 1024 chars via .slice(0, 1024) to prevent storage amplification from crafted headers.
Proof: GET /r/abc from 192.168.1.100 → ClickEvent: {ipHash:"a3f2e8...c1d9", userAgent:"Mozilla/5.0...", clickedAt:"2026-05-03T10:00:00Z"}. SELECT ip FROM click_events → column does not exist. Raw IP is never persisted.
Reasoning: Under GDPR Article 4, IP addresses are personal data. Storing them raw creates a breach liability — if the database leaks, every visitor's IP is exposed. Salted hashing preserves the analytics value (count unique visitors, detect click fraud by repeated hash patterns) while making reversal computationally infeasible. The per-deployment salt means a precomputed rainbow table from one installation is useless against another. Truncating UA/Referrer prevents a 64KB crafted User-Agent from consuming disproportionate storage per click.
