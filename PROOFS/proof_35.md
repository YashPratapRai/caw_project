Title: Encoded Scheme Bypass Prevention — Pre-Parse Validation
Demonstrated: URLs with percent-encoded dangerous schemes (javascript%3A, data%3A) are rejected before the URL constructor normalizes them. The bypass vector is closed at the raw-input stage.
Technical detail: SafeRedirectUrlConstraint runs four regex checks on the raw string before calling new URL(): disallowedSchemePattern (/^(javascript|data|file):/i), encodedSchemePattern (/^[a-z][a-z0-9+.-]*%3a/i), encodedSlashHostPattern (/^https?:%2f%2f/i), and backslashHostPattern. These fire before any normalization occurs.
Proof: POST /links with long_url:"javascript%3Aalert(document.cookie)" → HTTP 422 {"error":"long_url must be a safe http or https URL.","status":422}. Payload blocked; never stored.
Reasoning: The URL constructor decodes %3A to : during parsing. A post-parse check sees protocol "javascript:" and rejects it — but only if the validator runs after parsing. If any code path uses the raw string before the URL object is constructed, the encoded scheme executes. Pre-parse regex catches the attack regardless of downstream handling. This is why OWASP recommends validating before normalization: the raw input is the attacker's actual payload, and normalization can hide it.
